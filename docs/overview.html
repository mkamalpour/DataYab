BEFORE YOU BEGIN

The questions worth asking.

Clear expectations make a better first session—and a better presentation.

Browser, desktop or terminal?

The three entry points use the same analysis backend. Choose the browser for a local workspace, Tkinter for desktop work, or CLI for a file-based task.

What if cleaning or training fails?

Invalid changes preserve the previous working state. Successful cleaning invalidates models that no longer match the data.

Does a high score mean the model is ready?

It describes the chosen evaluation. Repeated experimentation can influence your choice; confirm the final model on fresh, representative data.

A saved model will not load. What should I check?

Use a trusted package with matching dependency versions. Older incomplete packages need retraining; keep your original dataset and previous model rather than overwriting them while diagnosing compatibility.

05 / THE EVIDENCE

Evidence, scope and next steps.

Reliable documentation makes the boundary visible rather than promising perfection.

Recorded automated verification
23 offline synthetic-data tests passed with the existing Conda base environment.

  • Repeated model exploration can overfit choices to the holdout; validate final decisions on fresh data.
  • Prediction probabilities are uncalibrated model outputs, not guarantees.
  • Large datasets and model comparisons can consume substantial time and memory.

This presentation explains the documented project. Recorded checks describe a particular run, not a live CI status or a guarantee for every dataset. The page works offline and loads no analytics, external fonts or remote assets.
